# 推理引擎补丁豁免 — PR #3401

[English](./3401.md) | **中文**

依据[引擎补丁规则](../PR_REVIEW_CHECKLIST_zh.md)记录本次例外申请；本文不代表评审批准或正式 sweep 验收。

## 范围与修改

[GB200 启动器](../../runners/launch_gb200-nv.sh)为 GLM-5.2 AgentX **性能**测试点选择[组合安装脚本](../../benchmarks/multi_node/srt-slurm-recipes/configs/glm52-gb200-nixl-prefill.sh)：release C10/C12 使用 `disagg-mtp-variants.yaml:zip_override_mtp_agentx_frontier[0]`，nightly C45/C48/C128 使用 `disagg-dep8-mtp-variants.yaml` 中对应的三个命名 override。脚本先执行现有 torchao 安装，再仅在 prefill 进程中调用[源码哈希保护的补丁程序](../../runners/patch_glm52_nixl_sync.py)。Decode 与 frontend 的开关为零；eval-only 保留原有 torchao 安装路径，不执行此补丁。

补丁修改 SGLang 的 `srt/disaggregation/nixl/conn.py`，让 prefill UCX 由调用线程推进：同时关闭 agent 后台推进线程和显式 UCX backend 线程池，保留 strict sync。传输线程在现有 room 失败保护内绑定指定 CUDA GPU。仅设置 `num_threads=0` 无法关闭独立 backend 推进路径，因此不足以实现该候选方案。

镜像继续固定为 `lmsysorg/sglang:v0.5.17-cu130` 与 `lmsysorg/sglang:nightly-dev-cu13-20260805-211ee642`，Dynamo revision 为 `71eb001e17fa73c742f0afe1a6ed96836cb135fd`。模型 revision、拓扑、并发、时长、golden 验收与必需 PowerX 均不变。生成端维持 `SGLANG_NVFP4_CKPT_FP8_NEXTN_MOE=0`；补丁不修改模型权重或 draft 精度。

## 固定镜像为何需要例外

本次 C10 scoring 期间，原始 UCX prefill 路径在 NIXL 共享推进线程的 `cuEventQuery` 中发生原生段错误；nightly 恢复也遇到同类失败。Prefill 崩溃后无法完成性能测试或所需功率窗口。

[SGLang issue #35189](https://github.com/sgl-project/sglang/issues/35189)记录了匹配的 v0.5.17/NIXL 1.3.2 调用栈，[issue #23489](https://github.com/sgl-project/sglang/issues/23489)记录了更早的 GB200 案例。缺少 CUDA context 的解释来自上游假设，尚未证明是本次故障的根因。这些报告支持采取范围明确且受保护的临时方案，不代表通用引擎修复已经成立。

## 移除计划

待合适的上游镜像在不打补丁的情况下完成受影响 release 与 nightly 测试点，并满足 eval 覆盖及必需 PowerX，再替换临时方案。在同一 PR 中更新镜像/revision，删除补丁程序与角色开关，恢复普通 torchao 安装选择，并移除此豁免。仅关闭上游 issue 不满足移除条件；未经修改的替代镜像必须通过受影响测试路径。
