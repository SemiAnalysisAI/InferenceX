## Change and necessity

The installer adds `del g1_w, g1_s` after the completed `w13` stacks and before the
`w2` stack in `srt/layers/quantization/mxfp4_flashinfer_trtllm_moe.py`. These lists
hold shuffle inputs whose data has already been copied into the completed stacks.
Releasing them earlier changes temporary lifetime only. Tensor payloads, layouts,
arithmetic, target quantization, and shipped-default draft computation and precision
are unchanged. TP4 does not invoke the installer.

The [unmodified TP2 attempt](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/35652922434)
failed during target MoE loading, before KV allocation: `torch.stack(g2_w)` requested
1.05 GiB with 174.90 GiB allocated and 916.75 MiB free. Reducing KV allocation could
not address this load-time failure. The
[lifetime-only retry](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/35655013153)
reduced live allocation by 2.24 GiB but left 2.92 GiB in fragmented reserved blocks.
The recipe also enables PyTorch's supported `expandable_segments:True` allocator
setting for TP2, allowing that freed memory to satisfy the contiguous stack.

The installer accepts only the exact source SHA256
`0ff4ca142e71ec0baabc00844b4854e554c607c1a356ffe13419c59b1f51813c` and produces
`ac952f63bc9a01b43df8888be1188ca9696213e31372c65a8a438c7fbea840d5`.
It is idempotent for that result and rejects unknown source revisions.

## Upstream tracking and removal

No relevant existing SGLang issue or PR was identified in the 2026-09-21 searches
for MXFP4 loading-memory failures. No upstream issue has been filed for this local
fix, so an upstream PR/issue link is currently unavailable. The
[pinned upstream loader](https://github.com/sgl-project/sglang/blob/0f6761b54facebb47f2068f87ecccd8f14da3a0e/python/sglang/srt/layers/quantization/mxfp4_flashinfer_trtllm_moe.py)
identifies the affected implementation; it does not substitute for issue tracking.
The missing tracking link remains explicit for reviewer assessment.

Remove the installer, its TP2 invocation, and this waiver when an unmodified
upstream nightly loads this checkpoint at B200 TP2 without the measured peak-memory
failure and passes full GSM8K plus the canonical AgentX sweep. Recheck whether the
allocator setting is still needed. A new image whose source hash differs must be
audited rather than silently accepting a broader patch target.
