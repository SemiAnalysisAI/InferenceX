## 补丁内容

配套的 [Dynamo 与 SGLang 补丁](../../benchmarks/multi_node/srt-slurm-recipes/configs/glm52-b200-c48/README_zh.md)分别基于 Dynamo `c3e05f0244ae6264d7953f68e2499c6dc2f54723` 和 SGLang `0084030179bfba86bfeb6d43f7997d4076329d2c`。Dynamo 原生 prefill router 将较晚出现的 prefill 错误传回原请求；Python handler 识别流式 abort 响应，并在已知请求注册、派发后按顺序取消。SGLang 将失败传输的缓冲区隔离至实际归属 worker 退出；仅本地 `srun` 退出不足以释放或复用资源。

启动器设置 1800 秒请求失败预算，这不是已验证的延迟上界。[清理监视器](../../runners/watch_glm52_b200_c48_cleanup.py)核对精确 job、user、runner、output 身份；在明确失败或清理信号后等待 300 秒，若 worker 尚未退出，只取消该 job。单个计分请求错误不会触发此保护或改变验收阈值。

工作步骤退出后，仅允许该作业的 `batch` 和 `extern` 步骤在原分配时限内继续生成 CPU 报告；必须等到分配终止且所有步骤退出，才能确认清理完成。

[安装器及 manifest](../../benchmarks/multi_node/srt-slurm-recipes/configs/glm52-b200-c48/)核验原始源码、应不存在的文件和原生二进制身份，再核验安装结果。配套产物固定使用构建收据 SHA-256 `27aa9a6eb223616d956dd7d507c0e26839cadcfb84339179898ff3a502ccbcba`。源码版本、依赖锁、软件版本和 release features 保持固定，审查过的补丁是明确的源码差异。原生 wheel 如实标记为 `cp310-abi3-manylinux_2_39_x86_64`，不宣称支持 `manylinux_2_28` 或更广平台。Python/native wheel 哈希及构建步骤见上述 README。

## 原镜像的失败证据

[Run 36188119567 / job 108246573370](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/36188119567/job/108246573370)在初始 warmup 的 49/51 个请求后停滞，最终达到四小时分配时限，没有计分窗口。留存的 prefill 日志包含 `NIXL_ERR_REMOTE_DISCONNECT`；断连起因和独立 DP7 停滞仍未解释。精确版本检查发现 Python 忽略 abort 响应、原生 bootstrap 尾流丢弃错误，以及取消逻辑等待首个输出提供请求 ID。这些证据支持增加故障隔离，不证明最初故障已经修复或性能测试一定通过。
