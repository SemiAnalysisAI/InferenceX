## What changes and why

| Component | Narrow adaptation | Failure without it / tracking |
| --- | --- | --- |
| HIP V4.1 attention | Isolated preview low-ratio attention, indexer, sparse reduction and router helpers; adapt moved nightly APIs | V4.1 compression ratios 1/2 enter the V4 ratio-4/128 path and fail with `No indexer pool for compression ratio 4`. [SGLang #39857](https://github.com/sgl-project/sglang/pull/39857), continuing [#39186](https://github.com/sgl-project/sglang/pull/39186), tracks the upstream gfx950 implementation. |
| Block32 dense linear and norm | Use existing nightly Triton UE8M0 quantization/GEMM; preserve normalized BF16 input until the configured block32 linear | Generic dispatch selects CUDA-only JIT code; the HIP fused norm supplies incompatible block128 scales. #39857 tracks gfx950 block32 support, but uses additional native kernels rather than this exact adapter. |
| Shared expert activation | Wrapper around the nightly AITER masked SwiGLU kernel | TP4 partition width 576 is incompatible with the fused block128 alternative. #39857 contains HIP activation support; the local wrapper is not asserted identical. |
| FP4 low-ratio pool accessors | Preview split-buffer store/read methods over the existing allocation | Nightly lacks the required V4.1 payload/scale accessors. #39857 tracks the corresponding low-ratio/indexer support. |
| Host Engram pointers | Resolve registered CPU tables with `hipHostGetDevicePointer` for GPU gather; retain CPU tensors for loading | CPU and GPU virtual addresses differ on MI355X. [SGLang #35233](https://github.com/sgl-project/sglang/pull/35233) fixes this class of issue for HiCache, but does not establish Engram coverage. **Specific Engram upstream tracking remains pending.** The submitted recipe still uses GPU Engram. |
| HIP runtime binding | Resolve the host-table alias through the already-loaded process HIP runtime | ROCm10 `find_library` selects `.so.5` while PyTorch uses SDK `.so.7`; the mixed runtime crashes before teardown. Binding the existing runtime passes exact host gathers. Dedicated Engram tracking remains pending. |
| Wide KV-store offsets | Isolate the stock FlashMLA kernel with upstream int64 `loc`, selected only by HIP V4.1 pools | Byte offsets above 2 GiB wrap in int32; guarded actual GPU tests reproduce the wrong writes. [SGLang #40351](https://github.com/sgl-project/sglang/pull/40351), head `5df9051e60e3a49f6432dfc4af2a1e7c18c66a6b`, provides the arithmetic fix. |
| ROCm10 allocator | Set `PYTORCH_HIP_ALLOC_CONF=expandable_segments:False` | Full-model AITER graph-buffer IPC registration aborts with expandable segments; the paired native-allocator run serves real requests. Long-context memory/performance remain pending. |
| A8W4 runtime settings | Restore official preview defaults and its unchanged EP4 tuning CSV | Nightly defaults differ from the preview's model path. [AITER #5562](https://github.com/ROCm/aiter/pull/5562) tracks these tuning rows; operator results there do not qualify this model. |
| Q-head normalization eligibility | Set existing `SGLANG_OPT_USE_FUSED_QK_NORM_ROPE=0` only in this recipe | V4.1 sets `q_head_norm=False`; nightly's fused HIP kernel always normalizes Q. At #39857 revision `7791f6c81b3958b9b2b9f99e135604f59052b467`, `use_fused_qk_norm_rope` requires both `attn.q_head_norm` and block `[128,128]`, matching the preview exclusion. |

Only the HIP V4.1 dispatch selects the compatibility package. Other model and CUDA
paths retain their original behavior. Checkpoint bytes, architecture, stock draft
loader/conversions and Markov settings are unchanged. Generic HIP block32 dispatch
is adapted, so this is not a claim that all quantization code is unmodified. The
adapter retains group size 32, E4M3 range, the `1e-10` absmax floor and upward
power-of-two scales. No custom WO_A precision patch is included.

## Validation and limits

The September 21 checks below have also been repeated on September 22 ROCm10.
[Detailed before/after evidence](../../benchmarks/patches/sglang_dsv41_rocm/evidence-rocm10.json)
records exact runtime library paths, the host-pointer backtrace, guarded offset
results and real DSpark responses. The installed wide-offset pool passes nine
boundary cases in eager mode and graph replay, plus the unchanged other-model
fallback. Native-allocator DSpark serving passed all three prompts with
19/23/25 generated tokens. These are bounded compatibility results, not full accuracy.
All six installer-target modules remain hash-gated and installation is idempotent.

MI355X checks passed for exact quantizer outputs, host gather, FP4 pool bytes/scales,
normalization/linear inputs, and activation outputs, including graph replay. Those
checks establish bounded compatibility, not full-model accuracy or performance.
Stock DSpark answered the same arithmetic prompt correctly at 52/719/2,159 input
tokens after disabling fused Q normalization (19/23/23 generated tokens). Before
that correction both longer cases repeated to the 384-token limit.

The [full 1,319-question real-verification run](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/35682996337)
was queued on the prior image at documentation time; the eight-example smoke was cancelled.
Full GSM8K on the new image, the DSpark performance curve and a
final full throughput-plus-eval sweep remain required. Upstream PR results use
different revisions/settings and are not evidence that this backport has passed.
Current qualification status is maintained in [PR #3343](https://github.com/SemiAnalysisAI/InferenceX/pull/3343).

## Removal and approval criteria

Replace the pinned base only after a released official ROCm nightly incorporates
the required V4.1 low-ratio/indexer APIs, block32 dense/norm and shared-expert paths,
correct fused-Q eligibility, 64-bit cache offsets, compatible graph-buffer allocation,
applicable A8W4 defaults/tuning, and single-runtime host aliases if
host Engram is enabled. Re-run real DSpark accuracy, long-context/cache checks and
the entire performance/eval matrix using the unmodified candidate image. Then
remove the installer invocation, compatibility package, copied CSV and obsolete
environment workarounds together; remove this waiver record in that cleanup PR.

covered by the linked work remain pending. No new upstream issue has been posted
