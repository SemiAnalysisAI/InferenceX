## What is patched

The SGLang `HiCacheController` and `HybridCacheController` direct load-back path
hands index readiness and existing per-layer copy submission to one device-bound
FIFO thread. The scheduler receives its producer ID before waiting for CUDA work.
The existing consumer boundary waits until the load events have been recorded;
device events still govern copy completion. Producer-slot reuse, reset draining
and error propagation preserve ordering. Submission errors fail closed without
publishing a successful ack. Non-direct index-copy/event ordering is retained.

The installer accepts only the two exact source hashes from revision `211ee642`,
or the exact already-patched pair. Unknown or mixed source states fail before
engine startup. The image, topology, HiCache capacity/backend/policy, watchdog,
workload, golden acceptance and draft precision remain unchanged.

## Why the unmodified image failed this benchmark

[Run 35925853577, attempt 1, job 107401191650](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/35925853577/job/107401191650)
hit the 300-second scheduler watchdog. The retained prefill stack places DP3 in
`device_indices.cpu()` from HiCache direct load-back while DP0/1/2 wait in the
DP-attention batch all-gather. Source `211ee642` performs this index copy while
building a batch, before entering that collective. A blocking device-to-host copy
can therefore prevent one rank from reaching the next host collective.

This is the observed failing path and a candidate synchronization-cycle mechanism,
not proof that every execution of the stock image fails. Earlier runs passed. A
prior kernel or driver fault could produce the same stack. Exact-runtime
reproduction is required before reporting the cause or repair as confirmed.

## Upstream reference and validation

[SGLang PR #34515](https://github.com/sgl-project/sglang/pull/34515), inspected at
`9c4edf986a05168cbbd1d447bba6849e48d6df56`, proposes direct-I/O helper dispatch.
This is a narrow load-only adaptation to the pinned earlier controller, excluding
its DSV4 allocator, write-back and MegaMoE changes. The upstream PR is open.

[CPU tests](../../runners/test_patch_glm52_hicache_sync.py) cover delayed device
readiness, consumer handoff, producer-slot reuse, FIFO order, device binding,
reset draining, errors, non-direct ordering, source rejection and idempotence.
Nine tests and Ruff checks passed locally. Both complete transformed source files
compiled and applied idempotently. No live GPU validation has been completed.
The affected final PR sweep and selected evaluation remain mandatory.

## Removal plan

Replace the pinned image with an upstream image that includes a verified repair
for this direct HiCache load synchronization path. First validate the unpatched
replacement on the same C48 1P x 4D workload with HiCache, draft flag 0, required
PowerX and selected evaluation. In that image-update PR remove the setup binding,
role gate, setup script, source patch and this waiver together. If the candidate
does not resolve the exact-runtime failure, retain its failure evidence and
withdraw it rather than weakening the watchdog or cache configuration.
