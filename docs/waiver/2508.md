## What is patched

`apply_k3_fp4_fp8asm_dspark_patches.sh` turns a fresh pull of the pinned base image into the exact
Kimi-K3 fp8-asm DSpark `FULL_AND_PIECEWISE` cudagraph container. Changes are applied as idempotent,
marker-gated diffs into the installed dist-packages plus one networked aiter rebuild; each is
re-checked by anchor grep in the script's VERIFY step. The **five vLLM ASM base patches** and the
**rejection-sampler NaN-argmax guard** that the original PR #2508 bundle carried are **upstreamed in
vLLM 0.27** and are no longer applied — the anchor check confirms they are native. The deltas the
base image still lacks:

| Upstream PR/issue | What it changes | Notes |
|---|---|---|
| aiter #4579 / #4575 (pin 55dbc4f47) | int-32 K/V offset fixes for the asm MLA kernels (mla_gluon >2 GB global_load) | networked aiter rebuild into a node-local `/opt/aiter-local` |
| aiter ASM split-K cudagraph guard | a16w16 GEMM fresh split-K semaphore safety under cudagraph capture (`patch_aiter_splitk_cudagraph.py`) — upstream aiter #4494 was **reverted** (#4709), so this workaround is kept | offline Python diff |
| DSpark fp8-asm enablement layer | routes small-head fp8 DSpark target verify to the ASM path + forces the draft causal (`apply_dspark_fp8asm.sh`) | local behavioral routing on `rocm_aiter_mla.py` |
| FlyDSL→torch decode-GEMM reroute | keeps the conc-24 FlyDSL capture hole out of the FULL decode graph (`patch_flydsl_decode_to_torch.sh`) | offline Python diff |
| KV-offload eagle prefix-veto | full-attn eagle prefix-veto fix in `offloading/scheduler.py::_lookup` — the only in-container change the DRAM KV-offload arm needs (`patch_offload_eagle_prefix_veto.py`) | offline Python diff |
| tuned K3 BF16 GEMM CSV | bundled `k3_patches/kimik3_bf16_tuned_gemm.csv` installed + merged → `merged_bf16_tuned_gemm.csv` and wired via `AITER_CONFIG_GEMM_BF16` | perf lever, not a correctness patch |
| triton 3.7.0 (AMD ROCm 7.2.0) | pip install `triton==3.7.0` + `tabulate` (the nightly ships 3.6.0) | dependency pin, not an engine-source patch |

## Why the unmodified upstream image cannot run this benchmark

The pinned `nightly-5a4c8d99` image carries the fp8-KV / DSpark-MTP vLLM fixes natively (the five ASM
base patches + the NaN-argmax guard are upstreamed in 0.27), but the stock image still cannot serve
this `kimik3-fp4-mi355x-vllm-agentic-mtp` config (fp8 KV cache, `FULL_AND_PIECEWISE` cudagraphs, DSpark
level-2 speculative decoding at TP8) without the deltas above:

- The base image ships aiter **without** the int-32 K/V offset fixes (#4579 / #4575) and takes memory
  faults on the mla_gluon >2 GB global_load during cudagraph capture; the node-local aiter rebuild at
  pin 55dbc4f47 is required.
- a16w16 split-K under cudagraph capture is unsafe without the ASM split-K guard (upstream aiter #4494
  was reverted by #4709, so the base image does **not** carry the fix).
- The fp8-asm DSpark small-head target verify is not enabled by default — without the fp8-asm
  enablement layer the verify falls into the Gluon flatten path, and the conc-24 FlyDSL capture hole
  breaks the FULL decode graph without the FlyDSL→torch reroute.
- The DRAM KV-offload arm (conc≥8) reads 0 external prefix hits without the eagle prefix-veto fix.

Without these, the server either faults during cudagraph capture, silently disables the fp8-asm verify
path, or serves the offload arm with a dead read path, so the benchmark cannot run as shipped on the
stock image.

## Removal plan

Retire `apply_k3_fp4_fp8asm_dspark_patches.sh` and its invocation from `kimik3_fp4_mi355x_vllm_mtp.sh`
once a ROCm vLLM nightly ships the remaining deltas natively (the aiter int-32 offset fixes at pin
55dbc4f47, an ASM split-K cudagraph-safe path now that #4494 was reverted, a default-on fp8-asm
small-head DSpark verify, and the KV-offload eagle prefix-veto). At that point bump the pinned `image:`
for `kimik3-fp4-mi355x-vllm-agentic-mtp` to that nightly, drop the patch script and its
`bash …/apply_k3_fp4_fp8asm_dspark_patches.sh` call, and delete this waiver in the same PR.
