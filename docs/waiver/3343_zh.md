## 修改内容及原因

| 组件 | 限定修改 | 原始故障与上游跟踪 |
| --- | --- | --- |
| HIP V4.1 注意力 | 独立移植预览版低压缩率注意力、索引器、稀疏归约与路由辅助代码，适配 nightly API | V4.1 压缩率 1/2 误入 V4 的 4/128 路径，报 `No indexer pool for compression ratio 4`。[SGLang #39857](https://github.com/sgl-project/sglang/pull/39857) 继承 [#39186](https://github.com/sgl-project/sglang/pull/39186)，跟踪 gfx950 支持。 |
| Block32 线性层与归一化 | 使用 nightly 现有 Triton UE8M0 量化/GEMM，保留归一化后的 BF16 输入供配置的 block32 线性层处理 | 通用分派调用仅支持 CUDA 的 JIT，HIP 融合归一化返回不兼容的 block128 尺度。#39857 跟踪同类支持，但使用额外原生内核，并非此适配器的逐字来源。 |
| 共享专家激活 | 封装 nightly AITER 掩码 SwiGLU 内核 | TP4 分片宽度 576 不满足融合 block128 路径的要求。#39857 包含 HIP 激活支持，但不宣称与本地封装完全相同。 |
| FP4 低压缩率缓存接口 | 在现有分配上移植预览版分离缓冲区存取方法 | nightly 缺少 V4.1 载荷/尺度接口；#39857 跟踪对应支持。 |
| 主机 Engram 指针 | GPU gather 使用 `hipHostGetDevicePointer` 返回的别名，加载仍保留 CPU 张量 | MI355X 的 CPU/GPU 虚拟地址可能不同。[SGLang #35233](https://github.com/sgl-project/sglang/pull/35233) 修复 HiCache 的同类问题，但不能证明覆盖 Engram。**Engram 专属上游跟踪仍待补充。** 当前配置仍使用 GPU Engram。 |
| HIP 运行时绑定 | 主机表别名从进程已加载的 HIP 运行时解析 | ROCm10 `find_library` 选择 `.so.5`，PyTorch 使用 SDK `.so.7`；混用导致清理前崩溃。绑定现有运行时后精确主机 gather 通过。Engram 专属跟踪仍待补充。 |
| KV store 宽偏移 | 仅 HIP V4.1 缓存选择上游 int64 `loc` 的原始 FlashMLA 内核 | 超过 2 GiB 的字节偏移发生 int32 回绕，自有内存保护的实际 GPU 测试复现错写。[SGLang #40351](https://github.com/sgl-project/sglang/pull/40351) 的 `5df9051e60e3a49f6432dfc4af2a1e7c18c66a6b` 提供算术修复。 |
| ROCm10 分配器 | 设置 `PYTORCH_HIP_ALLOC_CONF=expandable_segments:False` | expandable segments 导致完整模型 AITER 图缓冲区 IPC 注册退出；配对的原生分配器运行成功处理真实请求。长上下文内存及性能仍待验证。 |
| A8W4 设置 | 恢复官方预览默认值及未修改的 EP4 调优 CSV | nightly 默认设置不同。[AITER #5562](https://github.com/ROCm/aiter/pull/5562) 跟踪该调优表；其中算子结果不代表本模型验证完成。 |
| Q 头归一化资格 | 仅此配置设置现有开关 `SGLANG_OPT_USE_FUSED_QK_NORM_ROPE=0` | V4.1 为 `q_head_norm=False`，nightly HIP 融合内核却总会归一化 Q。#39857 的 `7791f6c81b3958b9b2b9f99e135604f59052b467` 版本要求 `attn.q_head_norm` 和 `[128,128]` 块大小，与预览版排除规则一致。 |

仅 HIP V4.1 分派选择兼容包；其他模型及 CUDA 路径保留原行为。检查点字节、架构、默认草稿
加载/转换及 Markov 设置不变。通用 HIP block32 分派经过适配，因此不宣称全部量化代码未改。
适配器保留 32 分组、E4M3 范围、`1e-10` absmax 下限和向上取整的二次幂尺度；不包含自定义
WO_A 精度补丁。
