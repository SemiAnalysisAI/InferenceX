# Runtime engine patch waiver for PR 2332

## Scope

This PR applies
`benchmarks/patches/vllm/glm52_b12x_ep_released_source.patch` to the installed
vLLM package only for the GLM-5.2 RTX PRO 6000 EP8 benchmark arm. The patch
changes `B12xEPExperts.workspace_shapes()` so a zero local-expert count is
accepted only when B12X has intentionally released its source parameters.
All other expert-count mismatches continue to raise an error.

The patch is checksum-gated to the digest-pinned Gilded Gnosis v20 image and
fails closed if either the patch or installed source differs from the validated
version. TP-only jobs do not apply it.

## Why the unmodified image cannot run this benchmark

Gilded Gnosis v20 prepares a packed B12X expert owner, then releases the source
MoE parameters to avoid retaining duplicate weights. The generic modular MoE
wrapper derives the local expert count from the released source tensor and
therefore reports zero during startup memory profiling. B12X EP compares that
value with the 32 experts retained by its prepared owner and aborts with:

```text
ValueError: B12X EP local expert metadata does not match prepared weights:
metadata=0, prepared=32
```

The failure occurs before KV-cache allocation or benchmark traffic in
[run 30186408654, job 89751956320](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/30186408654/job/89751956320).
The same image and recipe work with EP disabled.

## Upstream tracking

The modular MoE expert-metadata bug is tracked in
[vllm-project/vllm issue 49863](https://github.com/vllm-project/vllm/issues/49863).
The custom SM120 B12X EP integration used by this image originated in
[local-inference-lab/vllm commit b0d9820](https://github.com/local-inference-lab/vllm/commit/b0d9820e32a274037ba441836a9b9567ccff2229).

## Validation

The checksum-identical patched source was deployed over the pinned image on
8x RTX PRO 6000 and tested with TP8, DCP4, EP8, max 32 sequences, and CUDA graph
capture through size 128. Model loading, memory profiling, KV-cache creation,
and CUDA graph capture completed; `/health` returned HTTP 200 and a real chat
completion returned `READY`. The original metadata error did not recur.

## Removal plan

Remove the runtime patch and this waiver when the pinned image contains an
equivalent fix. Before updating the image digest, rerun the EP8 concurrency
16 and 32 benchmark cells plus their eval cell without the patch, and verify
that startup completes, inference succeeds, and no expert-count mismatch is
present in the server log.
