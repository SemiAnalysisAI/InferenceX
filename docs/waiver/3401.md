# Inference-engine patch waiver — PR #3401

**English** | [中文](./3401_zh.md)

Filed under the [engine-patch rule](../PR_REVIEW_CHECKLIST.md). This document describes the requested exception; it is not reviewer approval or formal sweep qualification.

## Scope and change

The [GB200 launcher](../../runners/launch_gb200-nv.sh) selects the [composite setup](../../benchmarks/multi_node/srt-slurm-recipes/configs/glm52-gb200-nixl-prefill.sh) for GLM-5.2 AgentX **performance** cells: release C10/C12 (`disagg-mtp-variants.yaml:zip_override_mtp_agentx_frontier[0]`) and nightly C45/C48/C128 (`disagg-dep8-mtp-variants.yaml`, the corresponding three named overrides). The composite first runs the existing torchao setup, then invokes the [source-guarded patcher](../../runners/patch_glm52_nixl_sync.py) only in prefill processes. Decode and frontend opt-ins are zero. Eval-only jobs keep the existing torchao setup and do not invoke this patch.

The patch modifies SGLang `srt/disaggregation/nixl/conn.py` to use caller-driven UCX progress in prefill: both the agent progress thread and the explicit UCX backend thread pool are disabled. Strict synchronization remains enabled. The transfer thread selects its assigned CUDA GPU inside the existing room-failure guard. Setting only `num_threads=0` would leave the independent backend progress path enabled and is insufficient.

The pinned images remain `lmsysorg/sglang:v0.5.17-cu130` and `lmsysorg/sglang:nightly-dev-cu13-20260805-211ee642`; Dynamo revision `71eb001e17fa73c742f0afe1a6ed96836cb135fd`, model revision, topology, concurrency, duration, golden acceptance and required PowerX remain unchanged. Generation keeps `SGLANG_NVFP4_CKPT_FP8_NEXTN_MOE=0`. This patch does not change model weights or draft precision.

## Why the pinned image needs this exception

The unmodified UCX prefill path produced a native segmentation fault in `cuEventQuery` from the NIXL shared progress thread during this campaign's C10 scoring. Nightly recovery also encountered this failure class. A crashed prefill cannot complete the benchmark or its required power window.

[SGLang issue #35189](https://github.com/sgl-project/sglang/issues/35189) reports the matching v0.5.17/NIXL 1.3.2 stack, and [issue #23489](https://github.com/sgl-project/sglang/issues/23489) records an earlier GB200 occurrence. The proposed missing CUDA-context explanation is an upstream hypothesis, not a demonstrated causal root for our failure. These reports motivate a narrow guarded workaround rather than establishing a general engine fix.

## Guards and evidence

The patcher accepts only SHA-256 `28da79ad06baa8c1b725bc98983ca570f82a73b49439873831505ab7f1eef601` and verifies output SHA-256 `c1c599fb66b35348ff7ed85b815f664f9b1d295b8c460589d953fe846606819f`. Unknown input, changed output, setup failure or invalid role opt-in stops setup before serving; the expected output is idempotently accepted.

[Native C10/C12 recovery run 36210188963](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/36210188963), attempt 1, tested candidate `6a0004996`. Its source-guard markers, full-window required PowerX and final cleanup were verified as integration evidence. Installed source files were not independently exported. Nightly C45/C48/C128 coverage remains pending at this waiver's preparation. Local selector tests and configuration expansion do not replace that runtime evidence or qualify the merged candidate.

## Removal plan

Replace this workaround when a suitable upstream image completes the affected release and nightly cells without the patch, including eval coverage and valid required PowerX. In the same PR, update the image/revision pins, remove the patcher and role opt-ins, restore the ordinary torchao setup selection, and remove this waiver. Upstream issue status alone is not the removal gate; the affected benchmark paths must pass on the unmodified replacement image.
