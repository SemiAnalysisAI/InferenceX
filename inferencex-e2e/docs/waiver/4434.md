## What is patched

The patch script makes two changes. Both are idempotent and serialized with `flock`.

| Upstream PR/commit | What it changes | How |
|---|---|---|
| sglang [#45450](https://github.com/sgl-project/sglang/pull/45450), merged as `c82f7141` | Moves the host work between DSv4.1 DSpark decode graphs into the graphs on the megakernel path. Its new code paths are opt-in `SGLANG_OPT_*` / `SGLANG_DSPARK_*` env gates, and only the c1 point sets them. | `git apply` of `dsv41flash-sglang-patches/sglang-pr45450.patch` to `/sgl-workspace/sglang`. This is the merged squash backported to `c1c287a4`, with context conflicts in 4 files resolved to the `c1c287a4` side. |
| sgl-nvidia-mega `3333e4cf` (main at [#16](https://github.com/sgl-project/sgl-nvidia-mega/pull/16), including #7, #15 and #18) | Replaces the image's plugin pin `d47deb33`. That pin predates SGLang's kernel regrouping (sglang#45112) and the `TopKConfig` split (sglang#44912/#44913), which `c1c287a4` already contains. With `d47deb33`, `--enable-nvidia-megakernel` fails at startup. | `git fetch` + `checkout` of the pinned commit in the image's editable checkout `/sgl-workspace/sgl-nvidia-mega`. Its `pyproject.toml` is unchanged since `d47deb33`, so no reinstall is needed. |

## Why the unmodified upstream image cannot run this benchmark

The batch-1 megakernel recipe depends on the #45450 env gates, which do not exist in `c1c287a4`. It also depends on a plugin that builds on current SGLang. No public `lmsysorg/sglang` nightly contains #45450.

- The dev-image builds of 2026-10-22 and 2026-10-23 failed at dependency resolution (the `python-dateutil`/`botocore` conflict addressed by sglang #45857 / #45860).
- SGLang's `docker/Dockerfile` still pins `SGL_NVIDIA_MEGA_COMMIT=d47deb33`.
