## What is patched

`apply_k3_container_patches.sh` reproduces, byte-for-byte, the patched Python source of the working
Kimi-K3 fp8-KV `FULL_AND_PIECEWISE` cudagraph container on a fresh pull of the pinned image. Changes are
applied as pinned pristine→container diffs (idempotent, marker-gated) plus one networked asm rebuild.
Net effect:

| Upstream PR/issue | What it changes | Notes |
|---|---|---|
| aiter #4474 | int64 KV stride (mla_gluon >2 GB global_load) | offline Python diff |
| aiter #4494 | a16w16 GEMM fresh split-K semaphore under cudagraph capture | offline Python diff |
| vllm #51171 | FULL cudagraphs for AITER MLA speculative decoding | offline Python diff |
| vllm #50578 | asm decode for non-divisor small head counts (12→16 @ TP8) | offline Python diff |
| vllm #51011 | fix fp8 KV cache decode on the AITER MLA backend | offline Python diff |
| vllm #51040 | extend FP8 asm MLA prefill to non-divisor small head counts | offline Python diff |
| vllm #50619 (PARTIAL) | cudagraph-exclude draft-attn layers + nvidia MLA fallback gate (`gpu/attn_utils.py`, `gpu/model_runner.py`, `kimi_k3/nvidia/mla.py`) | `rocm_aiter_mla.py` hunks NOT taken (conflict with #50578/#51011 asm strategy) |
| vllm #51682 | KDA packed decode: pass state-index stride to the kernel (native non-contiguous 1-D `state_indices`) | not strictly required (boots without it); kept for robustness |
| aiter #4521 | fp8 cp round-robin asm MLA verify kernels (qh16/qh32 qseqlen4 gqaratio16/32 cprr) + rebuild `module_mla_asm` | **needs network + hipcc + a GPU**: fetches binary `.co` and recompiles the asm module |
| DSpark PS verify (local) | route small-head fp8 DSpark target verify to the ASM persistent (PS) decode instead of the Gluon flatten (two edits on `rocm_aiter_mla.py`); supersedes the earlier HYBRID gluon-flatten verify | depends on aiter #4521 |
| triton 3.7.0 (AMD ROCm 7.2.0) | pip install `triton==3.7.0` + `tabulate` + `lm_eval[api]==0.4.12` | dependency pin, not an engine-source patch |

## Why the unmodified upstream image cannot run this benchmark

The pinned `nightly-cb8104839c` image predates the fp8-KV / DSpark-MTP fixes above. On this
`kimik3-fp4-mi355x-vllm-agentic-mtp` config (fp8 KV cache, `FULL_AND_PIECEWISE` cudagraphs, DSpark
level-2 speculative decoding at TP8) the stock image cannot serve:

- fp8 KV cache decode on the AITER MLA backend is broken without vllm #51011.
- The K3 small-head geometry (non-divisor head counts, 12→16 @ TP8) needs the asm decode/prefill
  extensions in vllm #50578 / #51040 and the aiter #4521 fp8 qseqlen4 verify kernels; the DSpark target
  verify otherwise falls into the Gluon flatten path that has no fp8 small-head verify kernel.
- FULL cudagraph capture for AITER MLA speculative decoding requires vllm #51171, and the mla_gluon
  >2 GB global_load / split-K-under-capture correctness fixes require aiter #4474 / #4494 to avoid
  memory faults during capture.

Without these, the server either faults during cudagraph capture or produces incorrect fp8 MLA verify
results, so the benchmark cannot run as shipped on the pinned image.

## Removal plan

Retire `apply_k3_container_patches.sh` and its invocation from `kimik3_fp4_mi355x_mtp.sh` once a ROCm
vLLM nightly ships all of the above (the vLLM #50578/#51011/#51040/#51171/#50619/#51682 fixes, the
aiter #4474/#4494/#4521 kernels, and an fp8 small-head DSpark verify path that makes the local PS-verify
routing unnecessary). At that point bump the pinned `image:` for `kimik3-fp4-mi355x-vllm-agentic-mtp` to
that nightly, drop the patch script and its `bash …/apply_k3_container_patches.sh` call, and delete this
waiver in the same PR.
