# Inference-engine patch waiver — PR #4629

Filed per [`docs/PR_REVIEW_CHECKLIST.md`](../PR_REVIEW_CHECKLIST.md) (image-provenance / patch item): the
setup script of the `infera-sglang` points patches the pinned SGLang image before serving, which the
checklist prohibits unless covered by a filled-out waiver.

## Config covered

- **Master config entry:** `glm5.2-fp4-mi355x-infera-sglang-agentic-disagg` in
  [`configs/amd-master.yaml`](../../configs/amd-master.yaml) (all three P/D shapes: 1P1D, 1P1D with a
  4-GPU decode, 2P1D)
- **Pinned image:** `lmsysorg/sglang-rocm:v0.5.22-rocm720-mi35x-20261018@sha256:8f7d8034546b17cc4ae57c63f3f65c584eb73e62378243d1416b8385aa7be286`
  (SGLang source `e9b22a08`)
- **Patch entrypoint:** the recipe's `setup_script: infera-sglang.sh`
  ([`benchmarks/multi_node/srt-slurm-recipes/configs/infera-sglang.sh`](../../benchmarks/multi_node/srt-slurm-recipes/configs/infera-sglang.sh)),
  which srtctl runs in every worker and router container; after installing Infera it runs
- **Patch script:** [`benchmarks/multi_node/srt-slurm-recipes/configs/infera-sglang-patches/apply.sh`](../../benchmarks/multi_node/srt-slurm-recipes/configs/infera-sglang-patches/apply.sh)

## What is patched

`apply.sh` edits the image's SGLang source in place (`/sgl-workspace/sglang`, the tree the image's
`sglang` package is installed from). The fix is anchored on the exact source it replaces, is
idempotent, and is checked by a marker afterwards; if it does not apply, the job fails instead
of serving unpatched.

| | Upstream PR/issue | What it changes | Why this config needs it |
|---|---|---|---|
| B8 | sglang issue [#46829](https://github.com/sgl-project/sglang/issues/46829), fix [#46918](https://github.com/sgl-project/sglang/pull/46918) (open) | Drop the hand-written Triton tile config of the MLA absorb BMM and let aiter pick its own (`models/deepseek_common/attention_forward_methods/forward_mla_rocm.py`) | GLM-5.2 prefill. For 193-256 rows `_absorb_bmm_config` (`:174`) asks for 4 waves per EU, which trips an LLVM assertion in Triton 3.7.0 on gfx950, the Triton this image ships; reproduced on 10-27. #46918 caps the request at 2 |

The four other fixes this config needed on the v0.5.22 nightly are upstream and in the pinned
nightly, so they are no longer patched: sglang
[#33059](https://github.com/sgl-project/sglang/pull/33059) (DSA indexer DP-padded rows on HIP),
[#46830](https://github.com/sgl-project/sglang/pull/46830) (no host syncs on rank-divergent DSA paths),
[#46820](https://github.com/sgl-project/sglang/pull/46820) (non-blocking KV metrics) and
[#21194](https://github.com/sgl-project/sglang/pull/21194) (PP middle stage without an embedding).

Not patched, by reading the same source: the DSA page-table rows (the recipe's
`index_share_for_mtp_iteration: false` keeps page-table and top-k rows equal), the non-final-chunk KV
wait event (only the overlap-scheduler path differs; PP prefill runs `--disable-overlap-schedule`),
and HiCache staged write-back on ROCm (the controller moves backup indices per pool on this source).

Nothing else in the image changes: Infera is installed with `--no-deps` at the master's router
version, and `infera.engine.sglang` starts SGLang's own `launch_server` unmodified.

## Why the unmodified upstream image cannot run this benchmark

- B8: a prefill batch that gets the 4-wave config (193-256 new tokens, such as the last chunk of a
  long prompt) aborts in Triton's LLVM backend; sglang#46829 reproduces the abort at 256 rows.

## Removal plan

When a pinned ROCm SGLang nightly contains #46918 (or another fix for #46829), the PR that bumps the
`image:` of `glm5.2-fp4-mi355x-infera-sglang-agentic-disagg` deletes `infera-sglang-patches/`, the
patch step in `infera-sglang.sh` and this waiver.
