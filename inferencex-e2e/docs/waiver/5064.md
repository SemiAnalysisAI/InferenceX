# Waiver: sglang#46945 for `qwen3.8next-fp8-mi325x-sglang-agentic-mtp`

**Image:** `lmsysorg/sglang-rocm:v0.5.23-rocm10-mi30x-20261110@sha256:368f0934d21d3cb2b23e208a0a96337f69534f9725df479d298fb3d890fffccb` (SGLang `670265cd4b`)

**What is patched:** `python/sglang/srt/layers/attention/qsa/mqa.py`, with the unmodified diff of
[sgl-project/sglang#46945](https://github.com/sgl-project/sglang/pull/46945) at `bba7137b`. On HIP it
caps the K pipeline depth of the QSA relative prefill indexer to the workgroup LDS; CUDA is
unchanged. It changes no precision, draft, architecture or FLOPs. The recipe's `setup_script`,
`qwen3.8next-mi325x-qsa-lds.sh`, applies `patches/01-sglang-46945-qsa-gfx942-prefill-lds.patch`.

**Why the unmodified image cannot run:** since
[sgl-project/sglang#45791](https://github.com/sgl-project/sglang/pull/45791) the kernel runs three
K stages, which need 81920 bytes of LDS; gfx942 has 65536. Every SGLang image with #45791,
including the `v0.5.23` release, fails on the first long prefill:

```
RuntimeError: Initialization failed: Requested dynamic shared memory 81920 exceeds device limit 65536 for kernel_kernel
```

With the patch the kernel runs two stages and matches `torch_qsa_mqa_prefill_relative` within 1.5e-6.

**Removal:** drop the setup script, the patch and this waiver when the pinned `mi30x` image contains
sglang#46945.
