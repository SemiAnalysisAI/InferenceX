# PR #5240: Hyperloom Qwen3.8 serving-stack waiver request

I request a temporary engine-patch waiver for [PR #5240](https://github.com/SemiAnalysisAI/InferenceX/pull/5240), affecting only `qwen3.8next-fp4-mi355x-sglang-agentic-mtp` and its nine AgentX points, C1/C2/C4/C8/C12/C16/C24/C48/C80. I provide this request for review; I do not record it as an approved exception.

## Simple explanation

I start from a publicly downloadable SGLang image and apply the exact changes supplied with the Hyperloom final-mainline package. Those changes add optimized execution paths and the tuning data selected by this recipe. The stock image can serve a baseline Qwen configuration, but it does not contain the complete optimized package. Removing the changes would test a different implementation and would not reproduce the package's specified behavior and reference results.

I therefore need an explicit exception to the rule that a serving image runs as shipped. I make the overlay reproducible from the image digest, the committed patches, the tuning tables and the recipe, and I plan to remove it once an official upstream image contains the required implementation.

## What I modify

I reach [qwen3.8next-hyperloom-patches.sh](../../benchmarks/multi_node/srt-slurm-recipes/configs/qwen3.8next-hyperloom-patches.sh) through `base.setup_script` in [agentic.yaml](../../benchmarks/single_node/srt-slurm-recipes/qwen3.8next/sglang/mi355x-fp4-mtp/agentic.yaml). Every serving worker, including natural-eval workers, takes this setup path. This is a container setup operation, not a cluster host-setup hook.

- I apply all 79 files in `sglang.diff`, including QSA selection and sparse attention kernels, GDN/linear-attention paths, hyperconnection fusion, model/loading and quantization handling, MoE/shared-expert routing, logits, speculative decode and Qwen monokernel paths, and scheduler/cache/checkpoint changes. This includes ReplaySSM, draft chain folding and the fused simulated-acceptance sampler selected by `SGLANG_INFX_SAMPLE_TAIL`. The diff also contains benchmark and test files; I retain the supplied aggregate rather than claiming those files are independent upstream PRs.
- I apply all 13 files in `aiter.diff`, including fused-MoE dispatch and sorting/quantization interfaces, HIP/OPUS sorting sources, FlyDSL GDN decode/verification and MXFP4 GEMM changes, and five included GEMM/MoE CSVs and a benchmark file. In particular, the sorting path adds `(E, topk, H)=(513,11,2560)`, GDN changes `KSTRIDE`/`KSPLIT`/`VITER` and snapshot writes, and the GEMM path uses typed global/LDS offsets.
- I remove only `/sgl-workspace/aiter/aiter/jit/module_moe_sorting_opus.so` and `/sgl-workspace/aiter/aiter/jit/build/module_moe_sorting_opus`, after checking that their resolved paths stay under the AITER tree. This lets the JIT module rebuild against the patched sorting sources instead of using a stale binary.
- I copy both external MoE tables listed above to `/opt/stack/configs/tables`. These copies can affect kernel selection and are part of this waiver, including any replacement of files at those destinations.
- I write `/sgl-workspace/.qwen38-hyperloom-patches` with the verified manifest digest. On a repeated setup I verify that digest and reverse applicability of both diffs, then reinstall the hash-checked tables.

I check both patches before applying either. A missing pin or asset, mismatched digest, unappliable patch, or different already-installed overlay fails setup. I keep the original patch/table bytes; only the manifest has an explicit LF checkout rule. I do not install a separate forked engine wheel through this setup.

## Removal plan

1. I map every retained production change to an upstream PR or issue, reconcile already-merged alternatives, and recover the outstanding series/source provenance. I keep the nightly image's own changes outside those package PRs.
2. I identify an official SGLang ROCm image from the upstream default branch containing the required SGLang/AITER changes and tuning support, and verify its build/source provenance.
3. I pin that image by digest, remove `setup_script`, both diffs, the external table overlay, manifest pin and JIT cleanup when the image supplies equivalent behavior. I remove this waiver's active dependency in the same change.
4. I record the affected config in a new performance changelog entry and run all nine points plus natural evals on the new image. I compare the effective recipe, draft precision and cache settings with the approved baseline before reusing or publishing results.

I retain the waiver until the reachable serving path no longer applies the overlay. I have no verified upstream merge or image-release date for the full aggregate; if Core declines the exception or the upstream work does not progress acceptably, I must use an approved unpatched configuration instead of merging this overlay.
