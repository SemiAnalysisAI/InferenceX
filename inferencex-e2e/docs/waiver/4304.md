# Serving-stack patch waiver — PR #4304

## Scope

The B300 Kimi K3 AgentX aggregate and disaggregated configurations use
`vllm/vllm-openai:nightly-1b2a666391f2a24228a1436b64d547c34cc6b6ce`.
Their container setup script is
`benchmarks/multi_node/srt-slurm-recipes/configs/kimik3-b300-efa-setup.sh`.
The script does not change vLLM, model weights, the draft model, the evaluation
harness or synthetic acceptance selection.

## Changes and reason

- Install EFA 1.50.0 userspace libraries, including the AWS OFI NCCL plugin.
  The upstream vLLM image does not include the EFA transport dependencies.
  The installer skips kernel modules, MPI and host limit changes.
- Backport upstream CUDA VMM synchronization support onto AWS libfabric
  `e83bf01a834a1a7c776d93efcaee3f8f28ff2705` (2.6.0amzn1.0).
  `libfabric-efa-vmm.patch` contains the adapted changes from
  [2c7d11a](https://github.com/ofiwg/libfabric/commit/2c7d11a50a3db03d26ad8260f8141621eee495f7),
  [790f0fb](https://github.com/ofiwg/libfabric/commit/790f0fb944f4cbeeb4381c99db6ba827ce5ded27), and
  [31f5ded](https://github.com/ofiwg/libfabric/commit/31f5ded159af13259b305e4389063fed0a22a096).
  Without these changes, EFA transfers using CUDA VMM allocations fail with
  `EINVAL` when the provider requests unsupported pointer synchronization.
- Build the EFA CUDA 13 Mooncake wheel from upstream
  [c3fa13ec](https://github.com/kvcache-ai/Mooncake/commit/c3fa13ecaf1038df933dcb784ff8ffe026381100),
  including the THP allocator from [Mooncake #4393](https://github.com/kvcache-ai/Mooncake/pull/4393).
  The released allocator uses small host pages, exhausting EFA registration
  resources for the configured 160 GiB segment per rank. The rebuilt wheel is
  identified as `0.3.13.post1+gc3fa13ec` rather than an unmodified release.
- Set `NIXL_DISABLE_CUDA_ADDR_WA=1` for NIXL 1.5's existing device-context
  fallback. CUDA VMM allocations do not provide the owning context expected
  by its pointer-address workaround. This is configuration, not a NIXL patch.

The setup caches build products under the runner's mounted Hugging Face cache
with an exclusive build lock. Each serving container installs the same pinned
artifacts; a build failure prevents serving. All changes are container-local;
the script does not modify host drivers, huge-page settings or network configuration.

## Removal plan

Drop the libfabric patch once the EFA installer ships the three upstream
changes. Replace the Mooncake source build with an official EFA CUDA 13 wheel
once it includes #4393. Remove the NIXL environment override when its VMM
context handling supports the default path. Retain only the EFA userspace
installation if it is still absent from the pinned upstream image.
